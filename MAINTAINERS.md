# Maintainers

See `GOVERNANCE.md` for what a maintainer does and how the role changes.
Contact maintainers via GitHub — a private
[security advisory](../../security/advisories/new) for anything sensitive, or
by @-mentioning a handle below in an issue or pull request for anything else.
There is no published email alias yet.

`GOVERNANCE.md`'s two-person custody rule for infrastructure and secrets is
not yet met with a single maintainer — it becomes enforceable as soon as a
second maintainer joins. New contributors are welcome to grow this list;
see `CONTRIBUTING.md` to get started.

## Becoming a maintainer

There is no formal application. A contributor who has made a sustained,
trusted set of contributions (code, review, design, or triage) may be
proposed by an existing maintainer and added by consensus among current
maintainers. This is recorded as an update to this file in a pull request.

## Infrastructure custody

See `GOVERNANCE.md` §Infrastructure and secret custody for the list of
accounts and secrets a maintainer may need access to. As of this writing all
of it is held by @BeyersNel; recorded here so the gap is visible rather than
silent, and so it is the first thing addressed once a second maintainer
joins.
